# UniResolve — AI-Powered Unified Complaint Intelligence

## Problem Statement
This project addresses **PS5: Unified Omnichannel Customer Grievance Ingestion and AI Triage System**. UniResolve brings customer complaints from multiple channels into a single consolidated agent dashboard, automatically redacts sensitive PII, triages each complaint with generative AI (category, severity, sentiment, key issues), detects duplicate/systemic issues, tracks SLA breach risk, supports human-in-the-loop escalations, and generates regulatory compliance reports.

## How to Run Locally

### Option 1: Docker Compose (Quickest)
1. Clone the repository:
   ```bash
   git clone https://github.com/Krishaaashah/Uniresolve.git
   cd Uniresolve
   ```
2. Set up environment variables:
   ```bash
   cp backend/.env.example backend/.env
   ```
   *(Update any necessary API keys like `GEMINI_API_KEY` or `ANTHROPIC_API_KEY` in `backend/.env`)*
3. Build and launch all services:
   ```bash
   docker-compose up --build
   ```
4. Access the applications:
   - Frontend Dashboard: [http://localhost:3000](http://localhost:3000)
   - Backend Swagger API Docs: [http://localhost:8000/docs](http://localhost:8000/docs)

---

### Option 2: Manual Local Running (For Development)

#### 1. Running the Backend
1. Navigate to backend folder and set up virtual environment:
   ```bash
   cd backend
   python -m venv venv
   venv\Scripts\activate
   ```
2. Install python dependencies:
   ```bash
   pip install -r requirements.txt
   ```
3. Copy environment configuration and populate variables:
   ```bash
   cp .env.example .env
   ```
4. Seed the database with demo complaints:
   ```bash
   python -m app.seed
   ```
5. Run the development server:
   ```bash
   uvicorn app.main:app --reload --port 8000
   ```

#### 2. Running the Frontend
1. Navigate to the frontend directory:
   ```bash
   cd ../frontend
   ```
2. Install npm dependencies:
   ```bash
   npm install
   ```
3. Run the development server:
   ```bash
   npm run dev
   ```
4. Open your browser at [http://localhost:3000](http://localhost:3000) to access the dashboard.

## Project Structure
* `/backend/app/api/complaints.py` — REST endpoints for ingestion, resolution actions, replies, and reporting.
* `/backend/app/services/` — Core services:
  * `pii_scrubber.py` — PII scrubbing and entity masking logic.
  * `triage.py` — AI-based complaint classification, severity assessment, and draft generation.
  * `clustering.py` — FAISS-driven duplicate checking and systemic outage alerting.
  * `store.py` — SQLite/Postgres database transaction layer.
* `/backend/app/models/complaint.py` — Core Pydantic data schemas and validation rules.
* `/backend/app/main.py` — FastAPI startup, Lifespan tasks, and SLA breach monitoring.
* `/frontend/src/app/page.tsx` — Next.js main dashboard container.
* `/frontend/src/components/` — Reusable React UI component views (Dashboard, SLA Tracker, Clusters, Detail Dialogs, IngestModal with voice Speech-to-Text).

## Dataset
All data is 100% synthetic, generated by our team using the seed script (`backend/app/seed.py`). It populates the database with:
* 20+ realistic customer complaints across 6 channels (Mobile App, Email, Social Media, IVR/Call Center, Branch Visit, Web Portal).
* Diverse financial categories (Loans, Accounts, Credit Cards, UPI, Transaction Errors, KYC Verification).
* Dynamic duplicate groups (for systemic anomaly clusters) and timelines.
* Simulated Core Banking System (CBS) log mappings containing transaction history and customer profiles.

No real bank or customer records were used.

* Category Precision: 0.91 | Recall: 0.88 | F1-Score: 0.89
* Severity Accuracy: 93%

* Accuracy: 94% on identifying semantic duplicate complaints.
* Search Latency: <50ms for clustering incoming records.

## Known Limitations
* Generative features (Claude drafts and root-cause analysis) depend on active external AI API keys and internet availability.
* Native browser Speech-to-Text uses the Web Speech API which requires internet connectivity to communicate with Google's speech recognition servers and is not supported offline.
* SQLite works locally for quick demos; production hosting requires switching to a PostgreSQL deployment.
